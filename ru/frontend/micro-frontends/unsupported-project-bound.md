# Неподдерживаемые модули, привязанные к проекту

Поддерживаемый фронтенд-контракт Wippy переносим. Модуль, который намеренно требует приватного для проекта CSS фасада, приватных классов или иного специфичного для развёртывания фронтенд-допущения, имеет статус `UNSUPPORTED`.

Это не обычное исключение:

- Стандартная проверка соответствия возвращает ровно `UNSUPPORTED`.
- Стандартный CI завершается неудачей.
- Переиспользование, переносимость темы, обновления и поддержка не гарантируются.
- Владелец модуля отвечает за каждый потребляющий фасад и за миграцию.

Не называйте этот режим «нежелательным», «частично соответствующим» или «несоответствующим, но принятым». Канонический статус — `UNSUPPORTED`.

Режим привязки к проекту предназначен только для продвинутых сценариев и не представлен в Быстром старте или стандартных рецептах. Он не может отменить требования доступности, валидности HTML, безопасности или схемы бэкенда.

То, что весь проект предназначен для одного развёртывания, не ослабляет контракт молча. Неподдерживаемый статус должен быть явно указан в политике проекта и метаданных модуля, а стандартный сбой CI должен намеренно обрабатываться вне поддерживаемого процесса проверки соответствия Wippy.

Объявите статус в `wippy-fe.contract.json` в корне модуля, точно с приведёнными ниже
полем и значением:

```json
{
  "portability": "project-bound"
}
```

`mode` и другие псевдонимы не принимаются. Этот маркер заставляет стандартную
команду проверки соответствия вернуть `UNSUPPORTED` и завершиться с ошибкой; он не
предоставляет освобождения от требований.
