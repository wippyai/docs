# Провайдеры Iconify

По умолчанию Web Host использует онлайн-источники Iconify. Настраивайте `AppConfig.iconify.providers`, только если развертыванию нужен другой источник. Локальная коллекция Tabler на этой странице является явным вариантом для автономного развертывания и не меняет источник по умолчанию.

## Настройка провайдера

Ключи `providers` задаются по ID провайдера Iconify. Используйте пустой ключ (`""`) для встроенного провайдера или ID в нижнем регистре с дефисами для именованного провайдера. Каждое значение содержит непустой упорядоченный массив `resources` с HTTP(S)-источниками. Host проверяет источники по порядку и не добавляет публичный источник в заданный массив.

```ts
interface IconifyConfig {
  providers?: Record<string, {
    resources: string[]
    path?: string
    timeout?: number
  } | null> | null
}
```

По умолчанию `path` равен `/` и нормализуется со слешами в начале и конце. `timeout` по умолчанию равен 5000 миллисекундам. Допустимы положительные целые числа до 60000. В `resources` указываются источники. Не добавляйте учетные данные, запрос, фрагмент или базовый путь.

## Как использовать Wippy без сети

Для автономного развертывания нужно самостоятельно разместить копию коллекции на сервере, доступном браузеру. Публичный CDN Web Host работает онлайн и не предоставляет приложение или другие службы без сети. В выпуск Host входит `iconify/tabler.json`.

```ts
const config = {
  iconify: {
    providers: {
      "": {
        resources: ["http://localhost:5173"],
        path: "/iconify/",
      },
    },
  },
}
```

Для локальной проверки разместите результат сборки Host так, чтобы `dist/iconify/tabler.json` был доступен по `/iconify/tabler.json`. В развертывании используйте собственный источник и версионный путь:

```ts
const deploymentConfig = { iconify: { providers: { "": { resources: ["https://wippy-host.internal"], path: "/webcomponents-<host-release>/iconify/" } } } }
```

Замените `<host-release>` закрепленным выпуском Host. Сервер должен возвращать JSON с `application/json` и разрешать браузерные запросы от источника приложения. Iconify отправляет `?icons=...`; статическая коллекция игнорирует запрос и возвращает все данные. Поиск не поддерживается.

Коллекция основана на Tabler 3.41.1, лицензия MIT, автор Paweł Kuna. Метаданные указывают 6092 значка; источник содержит 6140 определений и 184 псевдонима. SHA-256: `cf18f905479c5ca5d0be13217e17d240deea3c457b70b2ae84bcaa0d5a98a51c`.

### Правильная раздача зеркала

Настройка статического сервера входит в автономную конфигурацию. Сервер должен возвращать файл с типом `application/json`, разрешать запросы браузера с источника приложения через CORS, сжимать JSON при поддержке браузера и возвращать настоящий статус 404, если коллекции нет. Не кэшируйте отсутствующий файл как успешный ответ. Для версионированных путей можно использовать неизменяемое кэширование. Для пути без версии требуйте повторную проверку с помощью `ETag` или `Last-Modified`.

Пример Nginx предполагает, что файлы находятся по пути `/srv/wippy/host/webcomponents-<host-release>/iconify/tabler.json`, приложение использует точно указанный ниже источник, а TLS-сертификаты настроены вне этого фрагмента. Замените источник и корневой каталог значениями своего развертывания. Этот фрагмент не устанавливает модули Nginx и не настраивает TLS:

```nginx
server {
    location ~ ^/webcomponents-[^/]+/iconify/ {
        root /srv/wippy/host;
        default_type application/json;
        add_header Access-Control-Allow-Origin "https://app.example.com" always;
        add_header Vary Origin always;
        add_header Cache-Control "public, max-age=31536000, immutable";
        gzip on;
        gzip_types application/json;
        gzip_vary on;
        try_files $uri =404;
    }
}
```

Для пути без версии замените неизменяемую политику кэширования политикой повторной проверки, например `Cache-Control: no-cache`, и включите `ETag` или `Last-Modified`. Перед использованием зеркала проверьте, что сервер действительно сжимает JSON, задает ожидаемые правила кэширования, CORS и MIME и возвращает настоящий 404 для отсутствующего файла.

## Именованные провайдеры и значки

Именованный провайдер задается как `@провайдер:префикс:имя`, например `@tenant:tabler:home`. Vue и пользовательский элемент используют одинаковое имя.

```ts
const namedConfig = { iconify: { providers: { tenant: { resources: ["https://icons.example.internal"], path: "/tenant/" } } } }
```

```vue
<script setup lang="ts">
import { Icon } from '@iconify/vue'
</script>

<Icon icon="@tenant:tabler:home" />
<iconify-icon icon="@tenant:tabler:settings"></iconify-icon>
```

Источник покрывает только запросы коллекций значков. API, шрифты и другие ресурсы Kickside требуют отдельной офлайн-поддержки.

## Сброс и обновление

Если `iconify` не задан в начальной конфигурации, используются онлайн-значения по умолчанию. Если поле отсутствует в последующем обновлении, текущая конфигурация Iconify сохраняется. `iconify: null` или `providers: null` сбрасывает весь раздел и удаляет именованные настройки. `null` для пустого ключа сбрасывает только встроенный провайдер. `null` для именованного провайдера отключает его пространство имен. Пропущенные ключи сохраняют маршруты. Пустой `providers` не выполняет сброс.

Допустимы только `providers`, `resources`, `path` и `timeout`. Недопустимое начальное значение игнорируется, а недопустимое обновление сохраняет последнюю корректную настройку. `timeout` задает общий срок для логического запроса и всех настроенных источников. Каждая попытка переключения использует оставшееся время этого срока. Полной коллекцией считается только побайтовое совпадение с закрепленной коллекцией Tabler и только при наличии Web Crypto SHA-256. Такой ответ кэшируется по URL конечной точки без параметров запроса. Остальные ответы кэшируются по полному URL вместе с запросом. Если `crypto.subtle` недоступен, например при небезопасном HTTP, адаптер использует отдельные ключи с параметрами запроса, а хранилище Iconify может продолжать применять собственный кэш значков. Общий лимит кэшей адаптера — 32 URL. Замена коллекции по тому же адресу не очищает сохраненные ответы, уже разрешенные значки или отрицательные результаты. Чтобы загрузить замену, откройте новый контекст браузера. Ошибки транспорта и некорректные ответы переводят запрос на следующий источник; корректный ответ без значка сообщает not found. `iconifyIcons` управляет загрузкой и регистрацией элемента `<iconify-icon>`, но не источником. AppConfig передает явно заданные данные дочерним приложениям. Схемы 2.0 и 2.1 мигрируют в 2.2. См. [Последовательность bootstrap](./bootstrap.md), [Инъекция CSS](./css-injection.md), [Proxy API](../micro-frontends/proxy-api.md) и [Facade](../../framework/facade.md).

## Provider trust and updates

Используйте только доверенные источники провайдера. Страница отображает содержимое значков как SVG-разметку. Обновления `SetConfig` от родителя должны включать текущее значение `$schema` — `wippy-context-2.2`, чтобы применялась актуальная проверка. Смена провайдера влияет на еще не загруженные значки; ответы из кэша и уже отображенные значки не очищаются. Откройте новый документ, чтобы проверить замену провайдера.
