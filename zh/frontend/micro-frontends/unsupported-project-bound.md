# 不受支持的项目绑定模块

Wippy 受支持的前端契约是可移植的。有意要求项目私有 facade CSS、私有类，或其他部署特定前端假设的模块，状态为 `UNSUPPORTED`。

这不是一种普通的例外：

- 标准合规检查返回的正是 `UNSUPPORTED`。
- 标准 CI 失败。
- 复用性、主题可移植性、升级和支持均不作保证。
- 模块所有者需要为每一个消费方 facade 及其迁移负责。

不要把这种模式称为"不推荐"、"部分合规"或"不合规但可接受"。标准状态就是 `UNSUPPORTED`。

项目绑定模式仅面向进阶用户，不会出现在快速上手或标准范式中。它不能免除无障碍、HTML 有效性、安全或后端 schema 方面的要求。

整个项目只面向一个部署，并不会悄悄放宽该契约。不受支持的状态必须在项目策略和模块元数据中明确标示，并在 Wippy 受支持的合规工作流之外有意地处理标准 CI 失败。

在模块根目录的 `wippy-fe.contract.json` 中用下面确切的字段和值声明该状态：

```json
{
  "portability": "project-bound"
}
```

`mode` 及其他别名均不被接受。该标记会让标准合规命令返回 `UNSUPPORTED` 并以失败退出；它不授予任何豁免。
