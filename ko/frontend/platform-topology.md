# 플랫폼 토폴로지

이 페이지는 아키텍처와 진단을 위한 참조 문서입니다. 전달 체인과 다이어그램은 시스템 경계를 설명하며, 실행 가능한 프로젝트를 제공하지는 않습니다.

## 전달 체인

| 단계 | 소유자 | 검증 |
|---|---|---|
| 소스 및 패키지 빌드 | 프런트엔드 모듈 | 패키지 빌드가 예상 엔트리 파일을 출력합니다. |
| 아티팩트 위치 | 배포 빌드 대상 | 빌드 명령이 `--outDir`을 받으며, Vite에 경로를 하드코딩하지 않습니다. |
| 레지스트리 엔트리 | 백엔드 모듈 | `view.page` 또는 `view.component`가 출력된 엔트리를 가리킵니다. |
| 제공 URL | 파일시스템 및 HTTP 레지스트리 엔트리 | 자산을 직접 요청하면 빌드된 JavaScript 또는 HTML이 반환됩니다. |
| 런타임 컨테이너 | Web Host | 페이지는 구성된 페이지 엔진, 즉 레거시 `about:srcdoc` iframe 또는 Web Fragment를 사용합니다. 컴포넌트는 보통 shadow DOM을 사용하는 사용자 정의 요소를 사용합니다. |
| 컨텍스트 | AppConfig 및 Wippy 패키지 | 라우팅, API 접근, 테마 데이터가 지원 패키지를 통해 전달됩니다. |

소스가 존재하거나 빌드가 성공했거나 레지스트리 엔트리가 유효하다는 사실만으로 다음 단계가 증명되지는 않습니다. 각 경계를 따로 검증하십시오.

## 페이지

`view.page`는 레거시 `about:srcdoc` iframe 또는 Web Fragment라는 두 엔진 중 하나에서 실행됩니다. 전역 `hostConfig.renderEngine` 설정이 기준 동작을 선택하고, 페이지의 `wippy.renderEngine`은 이를 따르거나 `iframe`으로 재정의하거나 배포 환경이 지원할 때 `fragment`를 요청할 수 있습니다. 애플리케이션 코드는 엔진과 무관하게 유지됩니다. 어느 엔진에서도 브라우저 위치는 지원되는 자식 경로 계약이 아닙니다. AppConfig와 `@wippy-fe/router`를 사용하십시오. 해당 패키지가 Wippy 경로 통합을 처리합니다.

`iframe` CSS 주입은 현재 기본 테마 스크롤바 스타일을 제공합니다. 이름은 역사적인 것이며 현재 역할보다 범위가 넓어 보입니다. 스크롤바 일관성을 위해 활성화하되, 레이아웃 리셋이라고 설명하지 마십시오.

## 웹 컴포넌트

`view.component`는 호스트 문서에서 실행되며 일반적으로 자체 shadow root를 소유합니다. CSS 선택자는 shadow 경계를 넘어 캐스케이드되지 않습니다. Web Host는 컴포넌트 구성에 따라 승인된 스타일시트와 facade CSS를 해당 root에 전달할 수 있습니다.

CSS 변수 상속과 스타일시트 주입은 서로 다른 메커니즘입니다.

- 공개 상속 변수는 호스트에서 shadow로 넘어갈 수 있습니다.
- 선택자 규칙은 해당 shadow root 안으로 전달될 때만 영향을 줍니다.
- 전달되었다고 해서 임의의 선택자가 이식 가능한 API가 되는 것은 아닙니다.

## 테마와 오버레이

facade가 PrimeVue 테마를 제공합니다. facade `custom_css`의 공유 `.p-*` 규칙은 유효한 테마 구현이며 호스트와 자식 모두에 쓰도록 의도했다면 전역일 수 있습니다. 호스트 전용 크롬에만 `.wippy-host-app`을 사용합니다.

테마 모드는 CSS 클래스 API가 아니라 AppConfig 상태입니다. 애플리케이션, 컴포넌트, 픽스처, 브라우저 테스트에서는 `@wippy-fe/proxy`의 `host.setThemeMode('auto' | 'light' | 'dark')`로 모드를 전환하고 `@theme`을 기다린 뒤 `host.getThemeMode()`를 확인합니다. AppConfig가 변경을 호스트-자식 전송 경로를 통해 전달합니다. 호스트는 자체 문서를 업데이트하고, 활성 iframe 및 Web Fragment 페이지 realm에 AppConfig를 다시 브로드캐스트하며, 웹 컴포넌트 root에도 모드를 반영합니다. `w-theme-dark` 또는 `w-theme-light` 클래스를 직접 강제하지 마십시오.

PrimeVue 오버레이는 teleport될 수 있습니다. 최상위 문서, iframe 문서, 재귀적으로 발견한 shadow root에서 실제 오버레이 root를 확인합니다. 일반적인 PrimeVue 배치를 가정하지 마십시오.

## 런타임 디버깅 순서

1. 백엔드가 수신 대기 중인지 확인합니다.
2. 백엔드 로그에서 예기치 않은 5xx 응답을 검사합니다.
3. 레지스트리 소유자와 제공 자산 URL을 확인합니다.
4. 정확한 패키지 빌드가 해당 자산을 출력했는지 확인합니다.
5. 직접 deep link가 지원되지 않는 경우 SPA를 탐색하기 전에 호스트 루트를 불러옵니다.
6. 탐색과 상호작용 후 콘솔 및 네트워크 오류를 검사합니다.
7. 테마 시나리오에서는 공개 proxy 테마 메서드를 호출하고 `@theme`을 관찰하며, 스크린샷을 승인하기 전에 `host.getThemeMode()`를 확인합니다.
