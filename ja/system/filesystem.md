# ファイルシステム

ファイルシステムエントリは、ディレクトリをバックエンドとするストレージ、または読み取り専用の埋め込みストレージをランタイムモジュールに公開します。このページは設定リファレンスです。YAML ブロックは完全なプロジェクトではなく、個別のエントリの断片です。

## エントリ種別

| 種別 | 説明 |
|------|------|
| `fs.directory` | ディレクトリベースのファイルシステム |
| `fs.embed` | 読み取り専用の埋め込みファイルシステム |

## ディレクトリファイルシステム

```yaml
- name: uploads
  kind: fs.directory
  directory: "/var/data/uploads"
  auto_init: true
  mode: "0755"
```

| フィールド | 型 | デフォルト | 説明 |
|------------|-----|------------|------|
| `directory` | string | 必須 | ルートパス |
| `auto_init` | bool | false | 存在しない場合にディレクトリを作成 |
| `mode` | string | 0755 | Unix パーミッションモード（8 進数） |
| `base` | string | 推論 | 相対パスの基準: `project`（プロセスの作業ディレクトリ）または `module`（所有モジュールのリソースルート） |

モジュールが所有するエントリで `base` を省略した場合、相対ディレクトリは所有モジュールのリソースルートを基準に解決されます。ホストが定義したエントリは、引き続きプロセスの作業ディレクトリを基準とします。モジュールエントリで作業ディレクトリからの解決を強制するには `base: project`、モジュールルートからの解決を明示的に指定するには `base: module` を設定します。モジュールの所有情報またはそのリソースルートを利用できない場合、ランタイムは相対パスを変更しません。

設定したモードは、その所有者ビットによって操作を制限し、新しく作成するファイルとディレクトリに要求されたパーミッションもそのモードでマスクされます。すべての読み取りビットがあり、実行ビットがない場合、ランタイムは実行ビットを追加します（たとえば、`0444` は `0555` になります）。バックエンドディレクトリには、オペレーティングシステムのパーミッションも引き続き適用されます。

<note>
パスは正規化および検証されます。設定されたルートディレクトリ外のファイルにはアクセスできません。
</note>

## 埋め込みファイルシステム

```yaml
- name: static
  kind: fs.embed
```

埋め込みファイルシステムは、エントリ ID を使用してパックリソースから読み込まれます。読み取り専用です。

<warning>
埋め込みファイルシステムは内部で使用されるため、通常は手動で設定する必要はありません。
</warning>

## 操作

どちらのファイルシステム種別も次の操作を実装します。

| 操作 | ディレクトリ | 埋め込み |
|------|-------------|---------|
| Open/Read | はい | はい |
| Stat | はい | はい |
| Lstat | はい | はい |
| ReadDir | はい | はい |
| OpenFile (write) | はい | いいえ |
| Remove | はい | いいえ |
| Mkdir | はい | いいえ |
| Rename | はい | いいえ |
| Truncate | はい | いいえ |
| Chtimes | はい | いいえ |

埋め込みファイルシステムへの書き込み操作はエラーを返します。
